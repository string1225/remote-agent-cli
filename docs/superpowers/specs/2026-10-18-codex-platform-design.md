# Unified Codex platform

Approved in chat on 2026-10-18, with local CLI independence clarified on 2026-10-19. The existing 139 model gateway remains a separate service. `/agents` is the account, personal token, installation and remote execution entry point; the production URL is `https://codex.sunny-string.cn/agents`. Implementation, local verification and successful live 139 acceptance are recorded in the companion plan. Core implementation commit [5b8107f](https://github.com/string1225/remote-agent-cli/commit/5b8107f) was pushed to `origin/codex/unified-codex-platform`.

## Accounts and ownership

Public registration always returns 403, including when legacy `ALLOW_SIGNUP=true` remains configured. With the server stopped, `remote-server admin create --username NAME --password-stdin` creates an administrator and `admin grant --username NAME` promotes an existing account, using `DATABASE_PATH`. Production account `string` was explicitly promoted during the 139 upgrade with its original password preserved; no anonymous first-user bootstrap is exposed. Administrators search/create accounts, disable/enable them, reset passwords and manage roles. Privilege changes serialize operator authorization and last-active-administrator protection in one transaction, including concurrent requests. Users change their own unique username and password after confirming their current password; passwords are 6–72 bytes. User IDs remain stable when names change. Existing accounts, sessions and device bindings survive the atomic migration to ID-keyed accounts and a username index; existing users remain ordinary users until explicitly promoted. Names contain 1–64 Unicode runes, are trimmed and compared using a shared Unicode SimpleFold canonicalization for identity and partial search, including sigma and Kelvin-sign equivalents. Control characters and empty names are rejected; migration conflicts abort without partial changes.

Sessions, device connections and tokens are checked against current account state. Disabling an account closes its device/browser connections and cancels its active model requests without interrupting other users. Registration followed by a fresh account check closes upgrade/start-versus-disable races. Username/password edits and admin password resets invalidate browser sessions; credential snapshots are checked transactionally to reject logins already using a reset password. Account management never returns password hashes.

## Model gateway and tokens

Personal tokens have a `ra_codex_` prefix and 32 random bytes of base64URL secret, belong to immutable user IDs and optionally to enrolled devices. Only SHA-256 token verifiers are stored. Creation returns the secret once in `{token,...metadata}`; lists contain `{id,userId,name,prefix,createdAt,lastUsedAt,revoked,agentId?}`. Users list/create/revoke their own tokens; administrators can list/revoke all tokens. Agent-authenticated setup returns `{baseUrl,token,model}` and keeps prior device tokens valid so a failed installation/configuration write preserves the existing connection. Device revocation also revokes its model tokens. Personal-token revocation blocks subsequent requests; account disable additionally cancels active requests.

`/agents/codex/v1` authenticates these tokens without browser session middleware and forwards only GET `/models`, POST `/responses` and POST `/responses/compact` to a fixed HTTP root with a literal loopback IP, normally `http://127.0.0.1:8088`. `CODEX_GATEWAY_URL` defaults to empty/disabled; nonempty configuration requires `CODEX_GATEWAY_TOKEN_FILE`, and `CODEX_MODEL` defaults to `gpt-6.1-sol`. The upstream credential replaces caller authorization and never reaches a browser or device. Browser Origin requests, credential/account-routing query parameters, Cookie/Proxy-Authorization, upstream account overrides, environment proxies and redirects are rejected or excluded. Requests are limited to 32 MiB, two concurrent requests globally and an independent 30-minute deadline. SSE is flushed immediately. Per-user context cancellation sets read/write transport deadlines before closing bodies, releasing slots even for partial HTTP/1 uploads and blocked output. Errors use `{error:{message,type}}` without upstream secrets. Existing `/openai/personal/v1` tokens and upstream OAuth state remain untouched.

## Installation and local configuration

The persistent `remote-agent` local CLI is independent of enrollment and remote-service enablement. Three installer modes share platform templates: `cli-*` installs only the tool, `codex-*` prompts privately for a personal token and configures local Codex, and device installers enroll then optionally configure Codex and start the remote service. `codex install/update --server URL` installs the official SHA-256-verified CLI without Node.js; `codex setup --server URL --token-stdin` works without device enrollment, while enrolled `codex setup` issues a new device token without invalidating the working prior configuration. Setup retains a compatible detected CLI and installs one when absent. `app install/upgrade` uses Windows Microsoft Store winget or macOS Homebrew cask `codex-app`; Linux App installation is unsupported here. `start`/`stop` manage the optional enrolled service and leave the local tool/data available. Device installer switches are Windows `-NoStart/-SkipCodex` and Unix `--no-start/--skip-codex`; CLI-only reinstall preserves service state. Installation updates user PATH through Windows user settings or the appropriate Unix shell files, without duplicate entries.

Unix installs use the complete official `codex-package-*` archives, retaining `bin/codex` and resources, with a relative symlink for the command entrypoint. Windows retains the architecture-named executable and auxiliary files and provides a `codex.exe` hardlink/copy alias. Companion files are published before the main entrypoint, with rollback on failure. Transfers have a 25-minute timeout; archives are limited to 256 MiB compressed, 512 MiB per file, 2 GiB extracted in total and 10000 entries. Archive links, special files and path traversal are rejected; the installed Unix entrypoint alias is generated separately.

The setup helper respects `CODEX_HOME`, creates private timestamped TOML backups, detects concurrent edits, preserves unrelated settings and authentication files, and writes atomically. It sets provider `sunny_agents` using Responses, `supports_websockets=false`, `requires_openai_auth=false` and private `http_headers.Authorization`, so GUI and background processes share the credential without terminal environment inheritance. It switches an explicitly configured default profile too, leaves other profiles and existing models alone, and normalizes legacy `extrahigh` to `xhigh`. Existing Remote Agent installations retain bindings, permissions, projects and history. Windows credentials are restricted to user/SYSTEM; Unix uses private modes, including backups.

The UI offers local tool installation, one-time token display and one-copy stdin configuration commands, as well as optional device enrollment. Download URLs never contain personal model tokens. A copied configuration command does contain its token and can remain in shell history or the clipboard; hidden interactive input/private stdin is the alternative, and leaked tokens must be revoked. Users fully restart Codex App and create a new local chat after setup. The model gateway does not provide the application's entire ChatGPT account/cloud/plugin service surface, and old desktop threads can retain their original provider.

## Web and execution

The workbench sidebar exposes local CLI help and proxy setup through “Codex 接入与帮助”, and administrator account management through “账号管理”, alongside personal tokens and self-service account settings. Relevant download/install/configuration guidance from `/openai/docs` is linked without changing old helpers. Remote requests continue running on each user's enrolled devices through the encrypted channel; local write policy, cancellation and streaming remain in force. Model API traffic is a separate HTTPS path through the trusted platform adapter; it is not persisted as central task history.

## Verification and deployment

Account/migration/Unicode, role races, session and token isolation, fixed proxy forwarding, SSE/partial-upload cancellation, TOML/profile preservation, installer modes and managed-stop regressions are covered. Full Go tests/vet, both JS syntax checks and six Agent builds passed for `20261019-codex-platform-r2`. Earlier Chrome flows and an isolated native Codex v0.157.1 authenticated SSE flow passed. The official Windows Codex 0.163 ZIP, all 167080091 bytes, passed SHA-256 verification, actual local installation and native `--version`. Canonical Linux and macOS packages passed actual extraction/installation and per-file SHA-256 comparison on the Windows host: Linux 43 files/429934293 bytes and macOS 41 files/365155871 bytes. These Unix checks establish package preservation, not native execution on those operating systems. The Codex 0.163 native provider rerun passed against an authenticated SSE test upstream, and Chrome reruns passed Unicode account creation, tokens, stdin setup, self rename/password/relogin, ordinary-user admin 403 and 390px layouts. Actual browser login and password changes were tested locally. Local checks do not imply live deployment.

Before production upgrade, stop the server and back up the database, old binary/dist, env, Nginx and systemd configuration with ownership/modes preserved. Migration happens on first database open, including offline admin commands. Provision a root:root 0600 gateway source credential through systemd `LoadCredential`, with the environment pointing to its private runtime credential path for DynamicUser. Group/other permissions are rejected except for Linux systemd runtime mode 0440 inside the environment-advertised, canonical, symlink-free `CREDENTIALS_DIRECTORY` at `/run/credentials/<unit>`. Systemd protects this credential namespace; the application validates paths and permissions without inspecting filesystem mounts. Ordinary group-readable files remain rejected. Keep existing OpenAI routes, old tokens and OAuth state unchanged; add only the intended site/subpath rules, 32m inference body limit and unbuffered 1800-second streaming. Docker defaults to gateway disabled; using a host loopback gateway requires a reviewed Linux host-network arrangement and a readable private mounted token, not a blanket default or `host.docker.internal`. Rollback stops the server and restores the database/binary/config set together.

The 139 r2 release was deployed and passed live account/model smoke acceptance on 2026-10-19.
