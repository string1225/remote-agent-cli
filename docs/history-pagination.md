# 会话历史按轮次加载

工作台打开 Web、IM 或管家会话时，默认只显示最近 2 轮用户消息及其 Agent 回复。顶部居中的“加载更多”每次向前补充 2 轮，并保留正在阅读的位置。历史读完后按钮隐藏；失败保留原内容和游标，可重试。草稿、附件、原生会话和本机历史数据不变。

## 协议

`sessions.get` 新增 `turns:2` 与可选的 `before`（不包含该序号）。客户端从本机 bbolt 历史末尾倒序查找用户轮次边界，只读取目标窗口，按序号升序返回；分片用户消息按相同 `turnId` 计为一轮。该轮全部回复、工具调用和状态记录均保留。

窗口仍受原有约 24 KiB 分页限制，长回复通过 `nextCursor` 继续获取。首个响应的 `historyEnd` 是本窗口固定的上界，后续请求携带此值作为 `before`，避免读取期间新到达的消息改变窗口。`olderCursor` 表示下一次加载历史使用的排他上界，0 表示已到最早记录。未指定 `turns` 的原增量读取协议继续使用。

网页加载完当前窗口后，继续从最新已加载序号增量轮询。加载历史和实时增量按序号合并去重，切换客户端、项目或会话后丢弃旧响应。

## 升级与验证

服务器、网页与客户端需升级才能减少历史传输量。旧客户端不返回 `olderCursor` 时，网页兼容其原有正序分页，在内存中保留完整结果，只展示最近 2 轮；后续点击从内存补充。因此旧客户端的首次读取仍有全量传输成本。缓存预览也只显示最近 2 轮，客户端历史始终为准，无数据库迁移。

验证入口：Go 的 `TestHistoryTurnWindow*`、`node --test tools/test-history-pagination.cjs`；安装 Playwright 后运行 `tools/test-history-pagination-ui.cjs` 验证桌面和手机布局、加载次数与滚动位置。
