1. 从 DeepSeek 原型中采用什么

研究对象为 dsh-superagent-prototype，固定提交 6337fc8。它的参考价值在于把任务、派工、执行轮次、线程通信和副作用分开处理。角色提示词决定如何分工，持久状态与 outbox 决定消息是否可靠到达。公开仓库是研究原型，不能据此认定已具备本库需要的跨客户端权限、安装更新和数据恢复能力。

采用：稳定身份

管家是长期存在的角色与工作区；模型进程按会话轮次启动。无需让三个模型永久占用执行槽。

采用：可靠副作用

持久派工、结果 inbox/outbox、稳定请求 ID、ACK 后确认交付。重启可以恢复尚未送达的结果。

采用：工程路由

结果保存真实客户端、项目、会话和回复引用。直接回复通过标识投递，不让上层模型重新猜测收件人。

保持现有 Go/网页/SaySo 结构和 139 中转边界，不引入另一套 Python 执行内核、P2P、STUN/TURN 或额外设备凭证。

3. 从用户指令到结果的完整流程

  1. 用户向 CEO 或任何管家下达指令，进入真实会话。管家查询同账号目录，选择执行客户端与管家。
  2. 调用 delegate_work。139 验证账号和来源会话，CEO 目标固定到默认主机；检查路径循环与最大深度 6。
  3. 139 保存稳定 workId、随机 replyHandle、路径和请求摘要，再经现有 WebSocket 下发。目标客户端幂等创建执行会话，来源客户端记录已接受的委派。
  4. 目标执行器使用原生上下文运行。单轮“已交给下游”不会作为最终完成结果上报；下游结果到达后，上层汇总轮次重新进入持久任务队列。
  5. 执行终态和最终文本进入结果 outbox；结果经 139 送到来源 inbox，事务写入结构化结果卡。相同结果 ID 只入库一次，收到 ACK 才标记已交付。
  6. 来源会话排队进行汇总，工程提示不伪装成用户消息。若来源也是受委派的会话，该汇总继续回报更上层，直到用户入口。

有其他子任务未返回时，结果标记为进度更新。CLI 接收确认、部分文本或未捕获的最终答案，不能单独作为“已完成”的证据。失败保留任务与会话引用，供检查或续办。

4. 跨级回复怎样减少路由时间

每张结果卡保存 workId / replyHandle / origin.clientId / projectId / sessionId，并携带经服务器校验的下游关联引用。CEO 收到客户端管家的汇总后，用户可以直接选择“回复叶子项目管家”。

普通派工

用户 → CEO → 客户端管家 → 项目管家

↘

结果上的直接回复

用户 → 139 校验 replyHandle → 项目管家的原会话队列

直接回复沿用下游原生上下文，省去中间管家的路由模型调用；执行后仍沿原回报链更新上层。弹窗明确显示收件管家，回复草稿按账号和 replyHandle 隔离。重试使用稳定 requestId，同一 ID 修改正文会返回冲突。

浏览器仅能回复本账号工作；设备工具仅能管理本会话派出的工作。关联引用必须是当前工作的后代；设备撤销、目标删除、身份不匹配或引用超过 30 天时返回明确错误，用户可打开原会话继续。普通父子会话工具的权限不扩大。

5. SaySo 是 CEO 的能力

  1. 从左上角 CEO 旁的 SaySo 进入全局讨论。录音由用户主动开始并授权麦克风。
  2. 讨论转写、分析产生 Action；用户审阅并标记“讨论完善”。
  3. 点击“派给管家”，选择客户端管家或项目管家。讨论和录音仍保存在 CEO 主机，执行发生在目标客户端。
  4. 本地先保存派工队列与稳定 run ID。网络调用在 SaySo 锁外执行；断线和重启后沿用相同请求重试。
  5. CEO 下单独建立真实“SaySo · Action 回报”会话。结果回到该会话，同时通过持久查询更新 SaySo Action 的状态和输出。

原项目 SaySo 继续保留，旧讨论与录音可以访问。现有旧项目入口的同项目派发保持兼容，新跨客户端派发从 CEO SaySo 进入。

Codex 与 Qoder 的单次调用均注入上述 MCP 能力和当前角色指令；配套 remote-agent skill 说明角色边界、自动回报与普通父子任务的区别。凭据从本机配置读取，不写入提示词和进程参数。

用户会话只展示工具调用摘要和必要错误，不展示目录树、技能正文、原始工具返回或完整构建日志。超长分块 JSON 工具事件被有界丢弃，后续正常回答可继续解析。

7. HTML 报告托管、更新与恢复

139 已支持 .html/.htm 文件的隔离静态预览，上传返回 previewUrl；原链接保留下载功能。预览使用不透明来源 sandbox，禁用脚本、外部网络和表单，支持内嵌 CSS 与 data 图片。

公开随机链接会在下次北京时间凌晨 4 点失效，适合一次性交付。长期报告库、权限、续期与撤销仍是后续产品能力；本报告的仓库源文件可长期保存。

Windows 直接交付 MSI，不以发布者签名阻塞本次交付。MSI 内置 core 安装后切到新 seed，避免“安装成功却继续执行旧在线 core”；保留上一运行版本，安装失败恢复整个 runtime 指针。旧签名在线更新通道的验证规则保留，过期通道不能覆盖更新后的 MSI。

已经建立 CEO 后，切换默认主机会拦截并明确保留原位置。全量迁移 CEO 工作区、原生会话、录音和回报路由尚未提供，不能通过切换指针静默创建另一个空 CEO。

默认主机的 unknown request type 来自旧客户端不支持待办 RPC。服务器会给出明确升级提示；更新支持该协议的客户端后才能操作。网页“更新成功”现在区分同版本无更新和真实激活新版。
