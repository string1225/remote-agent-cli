# 客户端修复与远程维护

## 指定目标修复

网页的客户端菜单 → 修复，显示固定的目标客户端 ID、系统类型和已登记的机器名。复制的命令包含 `connect --client-id <ID>`，并通过标准输入传递 15 分钟有效、仅限该目标的恢复授权。不要把完整修复命令贴到公开日志。

执行时先核对本机绑定 ID、站点、设备凭证和经过哈希的系统机器标识。全部匹配时沿用原凭证，只修复服务；本机没有配置、配置属于另一个客户端，或者系统机器标识不同，都会显示核对结果。已绑定记录被替换或本机原绑定被改变时，必须输入 `BIND`（也接受“绑定”）才继续，其他输入取消。自动化操作可明确传 `--force-rebind`；它不绕过目标恢复授权或固定 OS 校验。

强制改绑撤销目标旧设备的访问，使实际运行命令的电脑接管该客户端记录。本机配置先备份，并保存私有事务文件；网络响应丢失时重跑同一命令会核对已提交凭证，不会再次消费授权。旧后台进程不能把原绑定覆盖回来。

本机项目、会话、录音和未知配置字段保留，目标原电脑上的文件不会搬到本机。同账号且能够认证本机原绑定时，项目登记及机器人占用跟随本机转到目标 ID，原记录保留但凭证退休。跨账号或站点时，不擅自转移机器人归属；AK/SK 留在原配置备份中，活动配置移除这些渠道，需要重新配置。系统类型不匹配时拒绝改绑。

## 网页远程操作

客户端在线后，客户端菜单 → **更新与工具**：

- **更新客户端**：Windows、macOS、Linux 均从绑定站点取得签名版本，检查平台、架构、摘要和发布序号，在设备空闲时切换。Windows 使用固定更新服务；macOS/Linux 原子替换程序并在原 PID 内重新加载，保留现有 LaunchAgent、systemd 或其他启动方式。不能远程指定其他来源、强制中断任务或执行任意管理员命令。
- **安装／更新 Codex CLI**：下载官方完整包并校验，保留原安装备份，启动检测后立即切换到客户端管理的 Codex，不需要重启服务。模型账号和 Token 继续使用绑定配置，本操作不创建新的登录授权。

窗口显示准备、下载与校验、安装或切换、确认结果，以及下载量和前后版本。操作记录保存在客户端的 `maintenance.json`，最多 20 条，按客户端 ID 隔离。关闭窗口不取消操作；重新打开可查询进度。客户端更新引发暂时断线时，网页重连并校对已运行版本；失败回退会明确显示结果。网络中断后重试复用请求 ID，避免重复安装。

Windows 远程更新要求固定宿主协议版本 2（发布 MSI 1.1.2）。现有宿主版本 1 需要安装一次新版 MSI并授权；之后的业务 core 和 Codex CLI 更新均可由网页发起，无需重复 MSI 或 UAC。首次安装、绑定修复、系统权限或宿主升级仍属于本机维护。

旧 macOS/Linux 客户端首次启用此功能时，在目标电脑运行 `remote-agent update` 并重启客户端；之后使用同一个网页菜单更新，无需重新执行安装脚本、重新绑定、sudo 或改写服务注册。运行账号必须能写入当前程序所在目录；只读的系统安装目录会明确报错，不会自动提权。

macOS/Linux 的更新先校验 Ed25519 发布清单和完整下载，再暂停新任务并检查录音/任务状态，探测候选程序能否读取现有配置和历史。原程序保留为 `.previous`，程序路径通过原子替换始终存在。`config.json.runtime-update.json` 保存发布序号上限和启动事务；首次启动未完成或进程再次启动时发现上次启动中断，会恢复已校验的原程序，并保留失败程序 `.failed`。回退不降低发布序号上限。就绪只依赖本地启动检查，139 暂时离线不会触发回退。更新与普通命令行更新共用文件锁；启动事务进行中拒绝并行替换。

三平台清单分别为 `/updates/v1/{windows|darwin|linux}/{amd64|arm64}.json`。发布时先 `go run ./tools/build -version <版本>`，再用 `tools/release-sign` 签发六个平台清单；`-platforms windows` 可仅签发 Windows。私钥不进入客户端或服务器。macOS/Linux 的信任公钥编译在客户端中，网页和清单都不能替换信任根。

## 验证边界

普通测试使用临时配置、模拟凭据和官方包结构的原生 CLI fixture，验证恢复、去重、进度和工具生效。浏览器测试脚本为 `tools/test-device-maintenance.cjs`，需 Playwright 和 Edge，可通过 `PLAYWRIGHT_MODULE`、`PLAYWRIGHT_CHANNEL` 指定运行时。

真实 Windows 服务 SID 发起更新、重启后读取持久结果及 MSI/SCM 注册不变，纳入 `tools/msi/acceptance.ps1` 的一次性管理员 runner 验收。Linux/macOS 原生测试启动临时配置的真实客户端，通过 WebSocket 发起签名更新，验证 PID 保持、重新连接、结果持久化和数据保留；回退测试覆盖启动失败、启动中断、损坏包和过期发布。这些测试不注册真实 systemd 服务或 LaunchAgent，也不操作开发者的真实绑定或发送机器人消息。真实设备的开机、退出登录和自定义服务环境仍应单独验收。
