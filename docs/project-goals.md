# 项目目标、现状与验收

基线：2026-10-24。服务器管理账号、设备注册、保活、网页入口和业务中转；客户端负责实际工作和本地数据。Windows 正式交付 MSI + Windows Service，开机运行、退出登录仍在线。需求中的 `code` 指 **Qoder**。所有开发直接提交并推送 `main`。

## 系统关系

账号 → 多个客户端 → 多个项目 → Web 会话、置顶 IM 渠道会话、置顶 SaySo。项目是工作目录与 Codex/Qoder 执行器，图标区分执行器；客户端左侧是 Windows/macOS/Linux 图标，右侧灰/绿点表示离线/在线。客户端行的 + 添加项目，不再增加执行器分组层。

每项目最多一个飞书或钉钉渠道，一个机器人全平台只绑定一个项目。客户端直接连消息平台长连接，AK/SK 只持久存本机。网页和客户端间所有业务经 139 站点、持久 WebSocket 中转，无直连回退。详细关系、工具名称及任务通知流见 [session-model.md](session-model.md)，协议见 [architecture.md](architecture.md)。

## 数据与恢复基线

服务器持久化账号、设备和验证值、公共项目元数据、机器人指纹归属；不持久化任务正文、录音或 IM Secret。客户端保存配置、项目、Web/IM 历史、原生会话、SaySo 讨论与录音、后台任务状态和通知队列。网页配置 Secret 时会经可信 139 中转，两段 TLS 不等于端到端加密。

升级保留原目录和身份；任务中断后保留提示词、已输出内容及恢复 ID，标记待检查，不自动重复执行。解除 IM 绑定保留历史。SaySo 映射复用旧讨论/录音 ID。配置变更先验证、预占再原子落盘，失败保留原绑定。部署需停止服务备份数据库和凭证目录，程序与数据库成套回滚。

Go 单元/集成测试、JS 语法、浏览器预览、交叉编译、Linux race 和隔离 MSI 验收是代码验证；不能替代真实硬件退出登录、商店显示、真实机器人与真实模型授权的验收。
