# 聊天中的客户端文件路径

聊天中的 Windows 绝对路径链接（`C:/...`、`C:\...`）、UNC 路径和 `file://` 链接，点击后显示“客户端文件”弹窗，保留链接文字并提供完整路径、复制按钮和打开指引。独立行内代码中的这些路径同样可点击；代码块保留原样。

例如 `[一键开启工具](C:/Users/Public/Documents/WOL-Setup/Enable-WOL.cmd)` 会显示可操作的“一键开启工具”。点击、复制后，在生成该文件的 Windows 客户端电脑的资源管理器地址栏粘贴路径并按 Enter。手机或另一台电脑看到的是原客户端的路径。

这是路径查看与复制能力。浏览器不会读取或下载此路径的文件，也不会启动脚本、请求系统管理员权限或修改客户端配置。剪贴板不可用时，弹窗选中完整路径供手动复制；成功复制也不表示文件已打开或工具已执行。文件是否存在、管理员授权和 WOL 效果仍需在目标电脑检查。

本地文件路径在 Markdown 净化前识别，转换为按钮；其他链接继续经过 DOMPurify 与协议白名单检查。HTTP、HTTPS、邮件及站内链接沿用原行为，模型生成的原始 HTML 继续按文本展示。

回归验证：`node tools/test-markdown-files.cjs`（通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright）。测试使用模拟网页与剪贴板，不访问真实文件、设备或账号；覆盖截图中的路径链接、行内路径、编码文件名、UNC、键盘操作、复制失败、浅深色、手机横竖屏和危险协议过滤。`UI_WEB_ROOT` 可指定干净源码目录，`UI_BASE_URL` 可针对线上静态资源验证，API 请求仍模拟。
