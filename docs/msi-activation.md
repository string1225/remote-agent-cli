# MSI 设备激活

MSI 的安装完成页包含设备绑定码和四个独立选项，不另开激活程序窗口，也不要求登录浏览器。网页新增 Windows 设备返回一次性绑定码和预填码的安装命令；设备菜单可重新查看尚未使用的码，或重新生成并撤销原码。绑定码有效期 15 分钟，只允许设备所属账号查看；服务器复用现有 AES-GCM 密钥加密保存，不写入设备列表。

默认勾选随系统启动、配置 Codex、安装 Codex CLI；默认关闭“启动网页代理（github、google、openai）”。安装 CLI 时复用已有可用安装；配置 Codex 独立申请绑定账号的模型配置，修改前备份。网页代理沿用现有按域名分流实现（含这些域名的子域、ChatGPT），其他目标直连；系统代理启用前核对本机监听与中转就绪，关闭时恢复原设置。

取消随系统启动后，业务服务设为手动启动，本次仍启动；下次开机需手动启动客户端。已启用网页代理时，应保持客户端运行。服务宿主维护时读取原 profile 的 manualStart，升级/修复保留手动启动选择。已有本机绑定继续复用，激活码不会用于自动替换原设备或账号。

WiX 完成页调用内嵌的 .NET Framework 4 自定义动作，由原安装用户隐藏启动安装目录下的 seed core；通过 UTF-8 stdin 和结构化 stdout 交换选择、阶段进度与结果。绑定码是 Hidden MSI 属性，不进入自定义动作参数、用户选项文件或日志。用户级 Codex 与系统代理配置保留原用户身份，Windows Service 配置复用现有路径交接与 UAC。后台进程不显示额外窗口，系统仍可能显示 UAC 授权框。

绑定前私有保存拟用设备凭据；激活响应丢失或本地落盘失败后可用原码和凭据重试，不重复创建设备。绑定、安装 CLI、配置 Codex、配置服务和确认在线分别执行并报告结果；可重试失败步骤，MSI 安装不因附加配置失败而撤销。恢复文件位于原配置旁 `.activation-pending.json`，选项保存在 `.activation-options.json`；原配置、项目、会话、录音和凭证不删除。

普通验证包括 Go 全量测试/vet、网页浏览器测试、无副作用的原生子进程协议测试和 MSI 只读检查。标准构建运行 WiX ICE 与只读 Installer session 检查；受限服务账户可显式用 `-PackageOnly` 生成包并只检查数据库表，该模式不能替代完整校验。真实安装、UAC、SCM、退出登录及原生 ARM64 仍须在显式授权的一次性管理员环境中验收，见 `tools/msi/acceptance.ps1`。
